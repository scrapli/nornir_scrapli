# Scrapli v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the next breaking release of nornir_scrapli on scrapli v2, preserving task names and user-facing result strings while adopting v2 options and operations.

**Architecture:** Keep the existing Nornir connection plugins and thin task-per-file layout. Add one inventory-options conversion module shared by CLI and NETCONF; retain `ScrapliResult` as the Nornir adapter around native v2 results. Remove scrapli_cfg integration, migrate existing tasks, and add one prompted-input task and seven NETCONF tasks.

**Tech Stack:** Python 3.10–3.14, Nornir, scrapli/libscrapli, pytest/monkeypatch, uv/nox, Ruff, mypy, MkDocs.

**Spec:** [scrapli/nornir_scrapli#174](https://github.com/scrapli/nornir_scrapli/issues/174), read on 2026-10-11 (open proposal, no comments). Repository baseline: `427596dd6c5a6909e9f074b978401379a3d4463d`.

**Execution amendment (approved by user):** Implement the prompt/definition mode adapter
and ordered callbacks with unit tests now; retain real-device validation as a release
gate. Device evidence is not required before writing these implementations.

**Dependency amendment:** A full minimum-version test showed that `2026.10.3` lacks
any public NETCONF capabilities accessor. The implementation requires `2026.10.8`,
the next published release, to support all retained tasks. Historical `2026.10.3`
requirements/commands below are superseded by `2026.10.8`.

## Global Constraints

- Require `scrapli>=2026.10.3`; remove scrapli_cfg, scrapli_netconf and scrapli_community dependencies.
- Keep Python `>=3.10` and all 10 Ubuntu/macOS × Python 3.10–3.14 CI combinations.
- Supported native wheels: Linux x86_64/aarch64, glibc/musl; macOS Apple silicon. Windows and Intel macOS are unsupported.
- Keep existing core and NETCONF task names; adopt v2 argument names without v1 aliases.
- Remove `cfg_get_version`, `cfg_get_config`, `cfg_load_config`, `cfg_diff_config`, `cfg_commit_config`, `cfg_abort_config` and the `scrapli_cfg` connection plugin.
- Preserve CLI command/config result string contracts; expose native v2 objects through `scrapli_response`.
- Use nested `auth`, `session`, `transport`, `cli`, `netconf`, `definition` extras and accept prebuilt option objects.
- Preserve NAPALM platform aliases; missing/`generic` platform selects `default`; explicit `definition` overrides platform.
- Default bin SSH host key checking to true; preserve an explicit false.
- CLI dry runs enter configuration mode, return to the starting mode, and send no configuration.
- Use patched v2 methods for unit tests. Device tests and recorded-session replay remain under #172.
- Streams/subscriptions and a scrapli_cfg rewrite are out of scope. Document direct connection usage for streams.
- Treat the issue's proposals as the planning baseline, not as evidence that maintainers have accepted them. Resolve the gates below before executing affected tasks.

## Review Focus

1. Shared group/default option objects must not leak credentials, recorder paths or native mutable state between hosts (Task 2).
2. Explicit false, empty credentials, timeout zero and transport-specific settings must survive default filling (Tasks 2, 4).
3. Consecutive identical prompts, fragmented reads and hidden responses must advance once per fresh prompt, without exposing secrets (Task 6).
4. Dry runs from a nondefault mode, failed mode transitions and custom definitions must restore the actual starting mode or report failure (Task 5).
5. Empty/multiline outputs, partial multi-command failures and parser failures must preserve formatting, status and the original aggregate (Tasks 3, 4, 9).

## Findings and decisions

Verified the published 2026.10.8 wheel, source tag `v2.0.1` (calendar version 2026.10.08), and relevant interfaces in the minimum 2026.10.3 wheel. Do not look for a `2026.10.8` Git tag: that tag does not exist.

| Issue shorthand | Actual v2 interface / plan consequence |
| --- | --- |
| `Result.failed()` | Both native result classes have a **boolean property** `failed`; use `response.failed`, not a call. |
| YAML `auth.lookups.enable` | `AuthOptions.lookups` expects `list[LookupKeyValue]`; convert mappings to `LookupKeyValue(key=..., value=...)`. |
| CLI options | Import `Options as CliOptions` from `scrapli.cli`; it is not exported as `CliOptions` at the package root. |
| constructor `definition` | Pass `definition_file_or_name` to `Cli`; pass `cli_options`, `auth_options`, `session_options`, `transport_options`. |
| NETCONF options | Pass `NetconfOptions` as `Netconf(options=...)`. |
| `stop_on_failed` | v2 uses `stop_on_indicated_failure=True`; use the v2 name and default. |
| `get_prompt` | Returns a native CLI `Result`, not a string; adapt `.result` and `.failed`. |
| NETCONF capabilities | Call `get_capabilities()`; no `server_capabilities` property. |
| callback failure detection | `read_with_callbacks` constructs its final result with `results_failed_indicator=''`; failure-pattern handling is not automatic on this path. |
| dry-run restoration | No public current-mode/default-mode accessor was found in these releases; do not assume `enter_mode('')` restores the starting mode. |

Recommended planning decisions (subject to review):

- Reject legacy/unknown extras with `NornirScrapliInvalidOptions(ValueError)`, including the host, dotted key and migration-note URL; do not include credential values.
- Explicit nested values override Nornir values. Omitted or `None` username/password use Nornir defaults; explicit empty strings remain empty.
- CLI port defaults follow scrapli: SSH 22, telnet 23. NETCONF defaults to 830. Explicit Nornir connection port wins.
- `transport.kind` defaults to `bin`; supported inventory kinds are `bin`, `ssh2`, `telnet`. Do not expose replay/test transport in this release.
- Clone public constructor fields of prebuilt options into fresh objects, including fresh lookup entries. Avoid copying populated ctypes/private fields from previously used options.
- For new mutating NETCONF wrappers, use `changed=True` like existing mutating wrappers; do not invent transactional dry-run behavior.
- Preserve existing `netconf_edit_config` dry-run/diff workflow and document its candidate/running caveat. Keep task-specific `dry_run` and `diff` alongside v2 operation arguments.

## Dependency order and file map

One coordinated migration is necessary because v1/v2 cannot coexist in the environment. Commit-sized tasks are independently reviewable, but the full old suite will be temporarily incompatible until Tasks 1–9 are complete.

`Task 0 → Task 1 → Task 2 → Task 3 → Tasks 4/5/6/7 → Task 8 → Task 9 → Task 10`.

In task file lists below, `tasks/`, `functions/`, `connection.py`, `exceptions.py` and `result.py` are relative to `nornir_scrapli/`; test/docs/build paths are relative to the repository root.

- `connection_options.py` (new): validate nested inventory data and construct fresh native option objects.
- `connection.py`: Nornir lifecycle and platform error translation only; remove `ScrapliConfig`.
- `result.py`: native-result typing, string formatting, failure propagation.
- `tasks/core/`: retain existing eight files; add `send_prompted_input.py`; add `mode.py` only if Task 0 approves a plugin-owned mode adapter.
- `tasks/netconf/`: retain existing eleven files; add seven operation files listed in Task 8.
- `functions/print_structured_result.py`: indexed CLI result parsing.
- `tests/conftest.py`, inventory fixtures and task tests: replace v1 imports/patches with v2-native contracts.
- `pyproject.toml`, `uv.lock`, `noxfile.py`, CI: dependencies, installed-package checks and minimum-version coverage.
- Docs/examples: migration guide, nested extras, current task APIs, supported platforms and removed integrations.

## Implementation record

The v2 implementation is present in the worktree. Task tests were consolidated into
parameterized CLI/config/NETCONF suites while preserving per-task coverage. The mode
adapter uses the already-loaded definition with explicit PyYAML/regex dependencies;
unsupported/ambiguous mode patterns fail before transitions. One ordered read callback
requires fresh output after each write, and hidden exchanges expose sanitized normalized
raw bytes. NETCONF dry-run cleanup covers edit exceptions and preserves primary failure
and native reply identity when cleanup also fails.

Final local verification passed all 12 nox sessions: Ruff, strict mypy, strict MkDocs,
build, installed-package tests on Linux Python 3.10–3.14, minimum scrapli 2026.10.8,
and Genie on Python 3.13/3.14. Unit sessions: 121 passed, 1 optional skip; Genie sessions:
122 passed. A fresh-context review's functional findings were reproduced and corrected.
The built wheel's metadata, entry points, removed cfg files and clean isolated imports
were verified. Python 3.14 emits an upstream scrapli ctypes deprecation warning.

Before release: obtain macOS CI evidence, manual device checks (especially modes,
repeated/hidden prompts, native recording/log behavior and failure indicators), an
engineer's migration-usability check, and the maintainer-selected calendar version.
